# Part 25 — Full Glossary

## 25.1 Financial Terms Glossary

**Table 8.1 — Financial Terms**

| Term | Definition |
|---|---|
| **Revenue** | Total income generated from normal business operations before any costs are deducted |
| **Gross Profit** | Revenue minus Cost of Goods Sold (COGS) |
| **EBIT** | Earnings Before Interest and Taxes — operating profitability before financing/tax effects |
| **EBITDA** | Earnings Before Interest, Taxes, Depreciation, and Amortization — a proxy for operating cash generation |
| **Net Income** | Bottom-line profit after all expenses, interest, and taxes |
| **EPS (Basic/Diluted)** | Earnings Per Share — net income divided by (basic or diluted) shares outstanding |
| **Free Cash Flow (FCF)** | Operating cash flow minus capital expenditures — cash available to shareholders/creditors |
| **ROE** | Return on Equity — `net income / shareholder equity` |
| **ROA** | Return on Assets — `net income / total assets` |
| **ROIC** | Return on Invested Capital — `NOPAT / invested capital` |
| **ROCE** | Return on Capital Employed — a profitability measure relative to capital deployed |
| **Current Ratio** | `current assets / current liabilities` — short-term liquidity |
| **Quick Ratio** | `(current assets - inventory) / current liabilities` — stricter liquidity test |
| **Cash Ratio** | `(cash + cash equivalents) / current liabilities` |
| **Debt/Equity** | `total debt / shareholder equity` — leverage measure |
| **Net Debt** | Total debt minus cash and cash equivalents |
| **Interest Coverage** | `EBIT / interest expense` — ability to service debt |
| **Gross Margin** | `(revenue - COGS) / revenue` |
| **Operating Margin** | `operating income / revenue` |
| **Net Margin** | `net income / revenue` |
| **Asset Turnover** | `revenue / total assets` — efficiency of asset use |
| **Inventory Turnover** | How many times inventory is sold and replaced over a period |
| **Cash Conversion Cycle** | Days to convert investments in inventory into cash flows from sales |
| **P/E Ratio** | `price / EPS` |
| **PEG Ratio** | `P/E / earnings growth rate (%)` — contextualizes P/E against growth |
| **P/B Ratio** | `price / book value per share` |
| **EV (Enterprise Value)** | `market cap + total debt - cash` — theoretical takeover cost |
| **EV/EBITDA** | A capital-structure-neutral valuation multiple |
| **Dividend Yield** | `annual dividend per share / price` |
| **DCF (Discounted Cash Flow)** | Valuation method estimating value from projected future cash flows discounted to present value |
| **WACC** | Weighted Average Cost of Capital — blended required return on equity and debt |
| **CAPM** | Capital Asset Pricing Model — `cost of equity = risk-free rate + beta × market risk premium` |
| **Terminal Value** | The value of all cash flows beyond the explicit DCF forecast horizon |
| **Margin of Safety** | Percentage gap between estimated fair value and current price |
| **CAGR** | Compound Annual Growth Rate |
| **Altman Z-Score** | A formula estimating bankruptcy risk from financial ratios (Volume 5, Part 14.3) |
| **Piotroski F-Score** | A 9-point checklist scoring fundamental financial strength (Volume 5, Table 5.3) |
| **Graham Number** | A conservative intrinsic-value estimate from Benjamin Graham's value-investing formula |
| **Comparable Company Analysis** | Valuation by benchmarking multiples against similar publicly traded peers |
| **Residual Income Model** | Valuation based on book value plus the present value of expected residual (excess) income |
| **Dividend Discount Model** | Valuation as the present value of expected future dividends |
| **Book Value** | Total assets minus total liabilities (shareholder equity) |
| **Float-Adjusted Shares** | Shares outstanding excluding closely held/restricted shares, used in some market-cap calculations |

## 25.2 Technical Analysis Terms Glossary

**Table 8.2 — Technical Analysis Terms**

| Term | Definition |
|---|---|
| **OHLCV** | Open, High, Low, Close, Volume — the basic unit of price/volume data |
| **SMA** | Simple Moving Average |
| **EMA** | Exponential Moving Average — more weight on recent prices than SMA |
| **Golden Cross** | A shorter-term moving average crossing above a longer-term one (bullish signal) |
| **Death Cross** | A shorter-term moving average crossing below a longer-term one (bearish signal) |
| **RSI** | Relative Strength Index — momentum oscillator (0–100) measuring speed/change of price moves |
| **Stochastic RSI** | RSI applied to itself via the Stochastic Oscillator formula, more sensitive to short-term swings |
| **MACD** | Moving Average Convergence Divergence — trend/momentum indicator from two EMAs |
| **ROC** | Rate of Change — percentage price change over a lookback period |
| **CCI** | Commodity Channel Index — measures deviation of price from its statistical mean |
| **Awesome Oscillator** | Momentum indicator comparing recent market momentum to a longer historical period |
| **ATR** | Average True Range — a volatility measure |
| **Bollinger Bands** | `SMA(20) ± 2 × stdev(20)` — volatility envelope around price |
| **Keltner Channels** | ATR-based volatility envelope, an alternative to Bollinger Bands |
| **Donchian Channels** | Channel based on highest high / lowest low over *n* periods |
| **OBV** | On-Balance Volume — cumulative volume-based momentum indicator |
| **VWAP** | Volume-Weighted Average Price |
| **CMF** | Chaikin Money Flow — combines price and volume to estimate buying/selling pressure |
| **Accumulation/Distribution** | An indicator estimating whether a stock is being bought or sold based on price/volume |
| **Support** | A price level where historical buying pressure has tended to halt declines |
| **Resistance** | A price level where historical selling pressure has tended to halt advances |
| **Doji** | A candlestick with a very small body, signaling indecision |
| **Hammer / Hanging Man** | Candlesticks with small bodies and long lower wicks, context-dependent bullish/bearish reversal signals |
| **Engulfing Pattern** | A two-candle reversal pattern where the second candle's body fully covers the first's |
| **Morning Star / Evening Star** | Three-candle reversal patterns signaling a bottom or top |
| **Head and Shoulders / Inverse Head and Shoulders** | A three-peak (or trough) chart pattern signaling a trend reversal |
| **Double Top / Double Bottom** | A two-peak (or trough) chart pattern signaling a reversal |
| **Triangle (Ascending/Descending/Symmetrical)** | Converging trendline chart patterns signaling continuation or breakout |
| **Flag / Pennant** | Short consolidation patterns after a sharp move, typically continuation signals |
| **Cup and Handle** | A rounded-bottom pattern followed by a small consolidation, typically bullish |
| **Fibonacci Retracement** | Horizontal lines (23.6%, 38.2%, 50%, 61.8%, 78.6%) marking potential reversal zones within a trend |
| **Fibonacci Extension** | Levels beyond 100% used to project potential continuation targets |
| **BOS (Break of Structure)** | A Smart Money Concepts term for price breaking a prior significant high/low, suggesting trend continuation |
| **CHOCH (Change of Character)** | A Smart Money Concepts term suggesting a potential trend reversal |
| **FVG (Fair Value Gap)** | An imbalance in price where one side (buyers or sellers) moved price too quickly, often "filled" later |
| **Order Block** | A Smart Money Concepts term for a price zone where large participants are inferred to have placed significant orders |
| **Liquidity Pool / Liquidity Sweep** | Areas where stop-losses are presumed to cluster; a "sweep" is a brief move through that zone before reversing |
| **Premium / Discount Zone** | Smart Money Concepts framing of whether price is in the upper (premium) or lower (discount) half of a recent range |
| **Wyckoff Accumulation / Distribution** | A market-structure theory describing phases where large participants build or unwind positions |
| **Spring / Upthrust** | Wyckoff terms for a brief false breakdown (spring) or false breakout (upthrust) designed to trap traders |
| **Multi-Timeframe Analysis** | Examining the same instrument across several timeframes to check whether trend signals agree or conflict |

## 25.3 AI / Agent / Systems Terms Glossary

**Table 8.3 — AI, Agent & Systems Terms**

| Term | Definition |
|---|---|
| **LLM** | Large Language Model — used in InvestorGPT only for explanation/narrative, never calculation (Volume 1, Principle 3) |
| **RAG** | Retrieval-Augmented Generation — grounding an LLM's output in retrieved documents instead of its parametric memory |
| **GraphRAG** | RAG enhanced with graph traversal, enabling multi-hop reasoning across entities and relationships (Volume 3, Part 9.6) |
| **Embedding** | A numeric vector representation of text used for semantic similarity search |
| **Vector Database** | A database optimized for nearest-neighbor search over embeddings (ChromaDB in this system) |
| **Knowledge Graph** | A structured network of entities and typed relationships (Volume 3, Part 9.5) |
| **Consensus Engine** | The component that combines independent engine "votes" into one weighted recommendation (Volume 3, Part 6.4) |
| **Reviewer Agent** | The deterministic QA gate that checks math, citations, and contradictions before publication (Volume 3, Part 6.5) |
| **Rule Engine** | Deterministic sanity checks (e.g., DCF assumption bounds) that run before any LLM explanation is generated |
| **Event Bus** | A pub/sub mechanism decoupling engines from each other (Volume 2, Part 5.3) |
| **Workflow Orchestrator** | The component owning an analysis request's end-to-end lifecycle (Volume 2, Part 5.4) |
| **Analysis State Machine** | The persisted state model tracking exactly which pipeline stage an analysis is in (Volume 1, Part 2.4) |
| **Plugin SDK** | The interface contracts that let third parties add indicators/valuation models/providers without core changes (Volume 5, Part 15.5) |
| **Provider Pattern** | The architectural rule that every external data source is accessed only through a shared interface (Volume 2, Part 5.6) |
| **Trust Score** | A numeric ranking (Volume 5, Table 5.1) used by the Verification Engine to prefer higher-quality sources |
| **Confidence Score** | A 0–1 value attached to every verified metric and every recommendation, reflecting source agreement and data quality |
| **Evaluation Framework** | The benchmark suite measuring accuracy, latency, and hallucination rate across releases (Volume 6, Part 19.4) |

# Part 26 — Sample Prompt Library

Every prompt below follows the rule established in Volume 3, Part 7.3: **facts in, prose out** — the LLM receives already-verified, already-calculated data and is structurally forbidden from inventing or adjusting any number.

## 26.1 Financial Explanation Prompt

```text
SYSTEM:
You are the Financial Explanation Agent for InvestorGPT. You will be given a
JSON object of ALREADY-CALCULATED, ALREADY-VERIFIED financial metrics. Never
invent, adjust, or recompute any number. If a metric is missing, say "data
unavailable" — do not estimate it.

INPUT:
{"revenue_growth_cagr_5y": 0.182, "roe": 0.341, "debt_to_equity": 0.41,
 "source": "FY2025 Annual Report, verified against SEC EDGAR"}

TASK: Write a 2-3 sentence interpretation of financial health for a
beginner-level reader. Cite the revenue growth figure exactly as given.
```

```text
SYSTEM:
You are the Technical Explanation Agent. You will receive already-computed

TASK: Write a 3-4 sentence technical summary for an intermediate trader,
explicitly noting the 4-hour disagreement with the daily/weekly trend.
```

```text
You are the Valuation Explanation Agent. You will receive the output of

Explain the consensus fair value and WHY each model produced its result.
```

## 27.1 SQL — Materialized View for "Most Recent Analysis per Company"

```sql
CREATE MATERIALIZED VIEW latest_analysis_per_company AS
SELECT DISTINCT ON (company_id)
    company_id, id AS analysis_id, state, recommendation, confidence, completed_at
FROM analyses
WHERE state = 'COMPLETED'
ORDER BY company_id, completed_at DESC;

CREATE UNIQUE INDEX ON latest_analysis_per_company (company_id);

REFRESH MATERIALIZED VIEW CONCURRENTLY latest_analysis_per_company;
```

## 27.2 TypeScript — Polling Hook for Long-Running Analyses

```typescript
// frontend/lib/hooks/useAnalysisPolling.ts
import { useEffect, useState } from "react";
import { AnalyzeResponse } from "@/lib/types";

export function useAnalysisPolling(analysisId: string, intervalMs = 1500) {
  const [data, setData] = useState<AnalyzeResponse | null>(null);
  const [error, setError] = useState<Error | null>(null);

  useEffect(() => {
    let active = true;
    let timer: ReturnType<typeof setTimeout>;

    async function poll() {
      try {
        const res = await fetch(`/api/v1/analyze/${analysisId}`);
        const json: AnalyzeResponse = await res.json();
        if (!active) return;
        setData(json);
        if (json.state !== "COMPLETED" && json.state !== "FAILED") {
          timer = setTimeout(poll, intervalMs);
        }
      } catch (err) {
        if (active) setError(err as Error);
      }
    }

    poll();
    return () => {
      active = false;
      clearTimeout(timer);
    };
  }, [analysisId, intervalMs]);

  return { data, error };
}
```

## 27.3 Node.js — Webhook Signature Verification

For any future outbound webhook (e.g., notifying an external system when `ReportGenerated` fires, Volume 5, Part 15.6), payloads are signed so receivers can verify authenticity:

```javascript
// services/notifier/verifySignature.js
import crypto from "crypto";

export function verifyWebhookSignature(rawBody, signatureHeader, secret) {
  const expected = crypto.createHmac("sha256", secret).update(rawBody).digest("hex");
  return crypto.timingSafeEqual(Buffer.from(expected), Buffer.from(signatureHeader));
}
```

## 27.4 Worked Plugin Example — Ichimoku Cloud Indicator

This demonstrates the Plugin SDK contract from Volume 5, Part 15.5, implemented end to end for a real, non-trivial indicator.

```python
# backend/app/plugins/installed/ichimoku_cloud.py
import pandas as pd
from app.plugins.base import IndicatorPlugin

class IchimokuCloudPlugin(IndicatorPlugin):
    name = "ichimoku_cloud"

    def compute(self, ohlcv: pd.DataFrame) -> dict:
        high, low, close = ohlcv["high"], ohlcv["low"], ohlcv["close"]

        tenkan_sen = (high.rolling(9).max() + low.rolling(9).min()) / 2
        kijun_sen = (high.rolling(26).max() + low.rolling(26).min()) / 2
        senkou_span_a = ((tenkan_sen + kijun_sen) / 2).shift(26)
        senkou_span_b = ((high.rolling(52).max() + low.rolling(52).min()) / 2).shift(26)

        latest_close = close.iloc[-1]
        cloud_top = max(senkou_span_a.iloc[-1], senkou_span_b.iloc[-1])
        cloud_bottom = min(senkou_span_a.iloc[-1], senkou_span_b.iloc[-1])

        if latest_close > cloud_top:
            hint = "Price is above the cloud — bullish structural bias."
        elif latest_close < cloud_bottom:
            hint = "Price is below the cloud — bearish structural bias."
        else:
            hint = "Price is inside the cloud — no clear structural bias."

        return {
            "value": {"tenkan_sen": tenkan_sen.iloc[-1], "kijun_sen": kijun_sen.iloc[-1]},
            "series": {
                "senkou_span_a": senkou_span_a.tolist(),
                "senkou_span_b": senkou_span_b.tolist(),
            },
            "interpretation_hint": hint,
        }
```

```yaml
# backend/app/plugins/plugins.yaml
plugins:
  - module: app.plugins.installed.ichimoku_cloud
    class: IchimokuCloudPlugin
    enabled: true
```

No file inside `engines/technical/` is modified to add this — the Plugin Manager discovers and registers it from `plugins.yaml` at startup, exactly as specified in Volume 5, Part 15.5.
